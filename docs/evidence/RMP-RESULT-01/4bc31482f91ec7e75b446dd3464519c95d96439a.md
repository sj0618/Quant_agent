# RMP-RESULT-01 증적 묶음 (Quant_agent 기준선)

이 문서는 이전 저장소(`Qaunt_agent`, 팀 저장소 이전 전 사용하던 이름)의
`db/rmp-result-01-immutable-manifest` 브랜치에서 작성했던 동일 항목 증적
(`bd5c00e67bd058aadd9d63249e9952eca6b7155e.md`, subject
`476b7b64ac545dad0fc8fdbc644669007d35c232`)을 대체하지 않는다 — 그 문서는 자기 SHA의
기록으로 그대로 남아 있고, 그 SHA는 이 저장소의 히스토리에 **object 자체가 존재하지 않는다**
(`git rev-parse 476b7b64ac545dad0fc8fdbc644669007d35c232` → `fatal: Not a valid commit
name`). 즉 단순히 "조상 아님"이 아니라 완전히 별개의 object 그래프이며, 이 문서가 이
저장소 기준의 유효한 기록이다.

## 3. WBS 지정 검증 명령 — 실행 결과 및 limitation

WBS가 지정한 명령 문자열을 그대로 실행했다.

```text
cd service_db && pytest -q tests -k 'migration or result or ownership'
```

- working directory(명령 시작 시점): `<repository-root>`
- `cd service_db` 이후 실제 working directory: `<repository-root>/service_db`
- 결과: **`pytest: command not found`, exit code `127`**
- 원인: 이 환경의 `pytest.exe`는 `pip install --user`로 설치되어
  `%APPDATA%\Python\Python312\Scripts`에 존재하지만, 이 경로가 현재 셸의 `PATH`에
  없다. WBS 문서의 명령 문자열은 이 환경에서 **문자 그대로는 실행되지 않는다** — 이 사실을
  숨기거나 성공한 것처럼 기록하지 않는다.

실제로 사용 가능한 동등 명령으로 재실행했다:

```text
cd service_db && python -m pytest -q tests -k 'migration or result or ownership'
```

- working directory: `<repository-root>/service_db`
- exit code: `0`
- 결과: `27 passed, 3 skipped`(신규 저장소에는 `test_migration_restore_drill.py` 2건이 이 필터에 새로 포함됨 — P1-DB-01 관련, RMP-RESULT-01 범위 밖이라 이번 판정에서 제외; skip 3건은 `AnalysisJobArchiveMigrationTests`로 이 항목과 무관)
- RMP-RESULT-01 직접 대상 5건(`tests/test_analysis_result_migration.py`) 전부 PASS.
- §2에서 확인했듯 SQL 파일이 무변경이므로, 이 5건은 SQL 텍스트 static 검사라는 성격도 이전과 동일하다(라이브 PostgreSQL 실행 검증 아님).

**limitation**: WBS 문서의 명령 필드(`pytest ...`)는 이 로컬 환경 기준으로 정정이
필요하다 — 실제로는 `python -m pytest ...` 형태로 실행해야 한다. 이는 이 환경의 `PATH`
설정 차이이며, 구현이나 테스트 자체의 결함이 아니다.
